## Jisho の検索結果を完全に保持

Jisho プロバイダーはすべての発音と順序付きの仮名グループ、語義ごとのインポート可能な定義、語彙分類、JLPT・一般語タグ、出典 URL を返します。`study:library:provider` への登録で辞書機能を宣言します。異表記、品詞、語義の注記、制限、方言、関連語、帰属情報を含む出典レコード全体を、任意の非表示スキーマフィールド `dictionary_data` に JSON として保持します。

一致が一件なら開いている編集画面に直接反映し、複数なら横並びのプレビューから選択して確認します。語彙の検索は入力文と構成トークンを変更しません。読みと定義は即座に確定し、セミコロンで区切られた意味もそれぞれ個別の定義にします。不足する UI 言語の翻訳は Cognis の任意のローカライズ能力が担当します。モジュールは翻訳を捏造せず、英語を他言語欄に複写しません。出典 URL と完全な元データは非表示の `dictionary_data` メタデータだけに保存します。

スキーマ改訂 88 とモジュール・コンテンツパックのバージョン 2.2.84 で出典データのフィールドを公開します。ホストのプレビューですべての語義をインポートするか、定義数の上限内で語義を選択できます。リンクした語義にかかわらず、元の検索結果全体は保存されます。

## 漢字専用の検索

同梱コンテンツにない漢字は、単語APIではなくJishoの漢字専用ページで検索します。訓読み・音読み、意味、画数、学年、JLPTレベル、使用頻度を取り込みます。発音から読みの区切り記号を除き、元の表記はdictionary_dataに保持します。提供元の障害は空の結果ではなく検索エラーとして表示します。KanjiVGプロバイダーは筆順機能と対象フィールドを明示します。モジュール・コンテンツパックのバージョン2.2.85はスキーマ改訂88を維持します。

## Jishoリクエストの識別

Jishoの漢字・単語検索はCognisを明示するUser-Agentを送信します。これにより、教の検索を含め、Nodeの既定の識別情報で発生したHTTP 403を解消します。エラーログには安全なエラーコードと取得できたHTTPステータスを記録し、応答本文を保存せずに提供元の拒否、応答形式の異常、通信障害を区別します。モジュール・コンテンツパックのバージョン2.2.86はスキーマ改訂88を維持します。

## 非表示の辞書出典情報

Jishoの検索候補は、完全な出典レコードとともに正確な出典URLを非表示フィールドdictionary_dataに保存します。Cognisは出典リンクや結果ポップアップを表示せず、このメタデータを直接取り込みます。モジュール・コンテンツパックのバージョン2.2.87はスキーマ改訂88を維持します。

## 辞書の意味を個別に取り込み

Jishoの単語検索結果では、英語の意味をセミコロンでまとめず、それぞれ個別の定義として返します。返された意味自体に含まれるセミコロンも分割します。各定義に個別の出典識別情報を付け、非表示の元データにはすべての意味と提供元の項目を保持します。モジュールとコンテンツパックはバージョン2.2.88となり、スキーマリビジョン88を維持します。

## 辞書の発音リンク

辞書から取り込む発音は、全体を構成できる最長の一致を使ってインストール済みの仮名に解決します。きょやっくなどの複合文字と同じ文字の繰り返し位置を保持します。読みグループには正規の項目IDを順序付きで保存し、不足する文字がある読みを部分的にリンクしません。定義は一致するカードを再利用し、必要な場合は通常の編集処理で作成します。下位カードの作成は引き続きカルーセルを中心に行います。文字と助詞は提供元のみが作成する読み取り専用のレイヤーを維持します。文の編集画面では辞書検索を提供しません。

## 辞書のすべての候補

一致が一件なら開いている編集画面に直接反映し、複数なら横並びのプレビューから選択して確認します。語彙の検索は入力文と構成トークンを変更しません。読みと定義は即座に確定し、セミコロンで区切られた意味もそれぞれ個別の定義にします。不足する UI 言語の翻訳は Cognis の任意のローカライズ能力が担当します。モジュールは翻訳を捏造せず、英語を他言語欄に複写しません。出典 URL と完全な元データは非表示の `dictionary_data` メタデータだけに保存します。

## 辞書検索とキャッシュ

辞書キャッシュは Cognis core の `core:cache` が管理します。一時間後にクエリをコールドとし、次回利用時に変更を確認します。変更は十二時間の境界で公開し、変更がない内容は保持します。同時問い合わせは確認処理を共有し、確認の失敗時には正常なキャッシュを維持します。永続キャッシュは再起動後も残ります。モジュールは辞書問い合わせの予定や応答キャッシュを管理しません。Jisho に軽量な変更通知はないため通常の検索応答で確認します。手動の Refresh 操作はありません。ローカルリンクは現在アクセス可能な Library のカードを参照します。

## 文のインポート要件

Jisho の単語 API (`/api/v1/search/words`) は語形、読み、意味、タグ、品詞を返します。文全体の検索でも構成語が返る場合がありますが、JSON に文の翻訳、トークンの位置、活用の対応関係、助詞の結び付きは含まれません。例文検索はコーパスの検索であり、任意の入力の翻訳ではありません。信頼できるワンクリックインポートには、表層位置・基本形・品詞・文脈に応じた読みを返す日本語形態素解析器、文の翻訳提供元、活用を Cognis の変換記述に対応付けるモジュール側のグラフ計画処理が必要です。元の文と句読点を正確に再構成し、発音を既存の仮名へ解決し、既存の語彙・助詞・文字を優先します。作成できるのは不足する編集可能な語彙や漢字と定義だけです。文字と助詞は提供元専用のままです。ホストはグラフ全体、範囲、アクセス権、曖昧さ、重複、原子的な取り消しを検証します。Jisho は語彙と漢字の情報を補えますが、この処理全体は提供しません。実装が完成するまで文インポート機能を公開しません。

## 正式な検索結果

単語と漢字の問い合わせは、内蔵データに一致しても Jisho の正式な結果を取得します。内蔵データはネットワーク取得が明示的に利用できない場合の代替であり、仮名の解決はプロバイダー内で行います。一文字の漢字専用検索は訓読み・音読み、意味、画数、学年、JLPT、頻度を取得します。Cognis の User-Agent、15 秒のタイムアウト、安全なエラーログを使用し、通信障害を空の検索結果として扱いません。

## 安定した辞書検索

Jisho はホストからの要求に応じて最新の語彙と漢字データを取得します。単語や読みの完全一致を関連候補より優先し、通常かなで書く語はかな表記を維持します。Wikipedia の記事名だけの候補は除外します。読みがない場合に定義を発音として表示したり、発音を作り出したりしません。定義と元データは分けて保持し、すべてのキャッシュ方針は Cognis が管理します。

Cognis core は `core:cache` で辞書キャッシュを管理します。保存した検索は一時間後にコールド状態となり、次の利用時に提供元の変更を確認します。変更結果は十二時間の反映時刻まで保留し、変更のない内容は維持します。同時検索は一つの確認を共有し、確認失敗時は最後に成功した結果を保持します。状態は再起動後も残ります。モジュールは提供元のデータを取得するだけで、検索のスケジュールや独自の応答キャッシュを管理しません。Jisho に軽量な変更通知 API はないため、確認には通常の検索応答が必要です。手動の更新ボタンはありません。発音とカードのリンクは常に現在アクセスできる内容から解決します。

## 辞書の読みのグラフ

辞書の元データは作成画面と詳細画面で非表示のメタデータとして保持します。取得した発音には親カードと同じ公開範囲の非表示語彙カードを使用します。複数の読みを持つ漢字では各読みに非表示カードを作り、名前を元の漢字へ、発音を順序付きのかなへリンクします。読みが一つの漢字は直接かなへリンクします。単語全体の読みは利用可能な最も近い漢字の読みの構成要素と残りのかなで構成します。定義は非表示の読みへ直接リンクします。Cognis は提供元の識別子を解決し、通常のフィールド、レイヤー、依存関係、ACL の検証を通してグラフを一括保存します。文字と助詞の作成は提供元に限定します。同じひらがなの読みを繰り返すだけのカタカナ候補は、辞書がそのカタカナ表記を示す場合を除いて除外します。漢字の正式な音読みと実際の外来語の読みは保持します。

## 検証済みの操作ステージ

KanjiVG の筆順ファイルには別の上限付きモジュールキャッシュを使います。最大 512 件、正常な結果は 24 時間、存在しないファイルは五分間保持します。同時取得は共有し、失敗した取得は破棄します。このファイルキャッシュは辞書検索や画面操作を管理しません。Jisho と KanjiVG は `api/reuse/content.js` の決定的なデータ読み込みを共有し、筆順プロバイダーは `api/reuse/lookup-cache.js` を利用します。 モジュールとコンテンツパックのバージョン 2.2.96 はスキーマ改訂 88 を維持します。Jisho はホストの `study:library:provider` を通じて `searchable: true` と `dictionary` 能力を登録します。仮名・漢字・語彙を扱い、文の検索とプロバイダー所有の助詞の作成は対象外です。

## 一般的な辞書項目

同じ完全一致の候補では、Jishoのis_commonが付いた項目を先に表示します。完全一致は関連候補より優先します。Jishoは意味ごとの頻度を提供しないため、定義は元の順序を維持します。室のroomも、作成画面で順序が反転せず先頭になります。

## 辞書と活用

活用カード内では見出し、読み、定義を同じ列に揃えます。原形を使う操作は中立スタイルのボタンです。ドラッグ中は移動先の前後に縦の挿入マーカーを表示します。Jishoから読み込む語彙には対応する活用グループのタグを保存し、新しく作った動詞は親の構成に配置する前に活用選択を開きます。副詞の品詞も保持しますが、現在の日本語スキーマには副詞の活用セットはありません。

辞書プロバイダーはprerequisitesとして{ key, layer, label }の配列を返せます。作成画面で候補を選択した後、Cognisは指定の公開範囲で既存の複合文字カードを解決し、なければ辞書から取得して定義と読みのグラフを含むカードを作成します。この経路では原子的な文字と助詞を作成できません。主カードと非表示の読みの参照では、別名キーを正式なIDに置き換えます。語彙の入力は変更せず、読み込んだ表記リンクは入力が検索語と一致する間だけ使用します。検索結果を見るだけでは依存カードを作成しません。

不足する必須フィールドは、保存前に登録済みの補助検索プロバイダーから取得します。漢字の筆順パターンにはKanjiVGを使います。各漢字、定義、非表示の読みは、公開範囲を検証した１つのグラフとして保存します。

## 漢字の読みの表記

漢字検索では、Jishoのカタカナの音読みをひらがなに変換し、カードの発音と読みのリンクに使用します。僕には、しもべに加えてぼくが含まれます。変換後に同じ訓読みと音読みを重複排除し、ボクなどの元の表記は非表示の辞書メタデータに保持します。語彙のカタカナ表記と検索による重複した読みのフィルタリングは従来どおりです。

主な読みは、Jishoの一般的な完全一致の語彙に基づきます。僕はぼくを先に、その後にしもべを表示します。関連する語や漢字の読みとして記載されていない読みは順序に影響しません。語彙検索が失敗しても漢字の結果は使用でき、エラーは安全に記録されます。

## 学習の発音表示を統一

Study は公開の発音分類とスタイルを提供し、Library のプレビュー、詳細見出し、変化形、学習カードの答えと読み方の選択肢、描画領域で再利用します。IPA は元の表記を維持し、通常の読み方は選択したアプリ書体を維持します。日本語と英語の文スキーマはいずれも最低2つの単語参照を必要とします。

## 文字列の直接指定を禁止し翻訳キーを必須にする

AI向け指示では、すべての経路で英語のユーザー向け文字列の直接指定を禁止します。選択言語に値がない場合は英語のXMLリソースの同じキーを使用できます。英語の代替値も未定義または空の場合は、英語の直接指定、キー名、空の文字列を表示せず、明示的に失敗させます。翻訳の欠落によるエラーを握りつぶしてはいけません。

筆順検索は最大十六の書字単位に制限し、字形取得全体で十五秒の期限を共有し、百万バイトを超える応答を中止します。

## Studyモジュールの構成

コンテンツパックは`data/library/`に配置し、マニフェスト、スキーマ、コンテンツファイルを一つの取り込み・削除境界として扱います。初期デッキは`data/starter-decks.json`に残します。実行時プロバイダーは`api/dictionary/`と`api/strokes/`、決定的なファイル読み込みとバイト数を制限した応答デコードは`api/reuse/`に配置します。横断的なコンテンツ・ライフサイクルテストは`tests/`、プロバイダー・通信・APIテストは`api/tests/`に置きます。マニフェストは`api/routes/config/index.js`を`disabledApi`として宣言し、この入口では管理者限定の設定DELETEルートだけを登録します。コンテンツの取り込みやプロバイダーの起動は行いません。公開済みフロー識別子は維持します。

## 間を付けた合成と手動置換

初期録音は多言語ニューラルモデル Kokoro をオフラインで使用し、英語に `bf_emma`、日本語に `jf_alpha` を使用します。クリップは 128 kbps、開始前の無音 200 ms、終了後の無音 180 ms、上限付きピーク正規化、遅めの発話速度で生成します。モデルの帰属表示と Apache ライセンスは `data/audio/VOICE-LICENSE.txt`、声と処理設定は録音一覧に記録します。

文カードには任意の音声フィールドがあります。初回再生時に Cognis は全構成要素へのアクセスを認可し、最初の発音グループだけを選び、指定の変形を適用して、開始前の無音と単語・読点・文末の間を持つ一つの連続 WAV を生成します。録音は非公開でキャッシュし、構成音声のバイト列、読み、変形、間の変更で識別子が変わります。新規カードと既存カードの両方で必要時に生成します。通常の作成画面で音声をアップロードすると生成音声を即座に置き換え、明示ファイルを削除すると自動合成に戻ります。提供元は語の録音を提供し、Cognis が合成とキャッシュ方針を管理します。

## 参照データの収録範囲

日本語の参照カタログは同梱する公式 KANJIDIC2 データの全 13,108 字、英語のカタログは Open English WordNet の全 135,969 語彙項目（正規化キー 127,311 件）を収録します。別の遅延読込辞書プロバイダーであり、149,077 件のカードを起動時に一括取り込みするものではありません。Study 検索で参照辞書を選び、対応項目を通常のグラフ検証経由で取り込みます。意味や使用可能な読みがない項目は不明のままとし、発音・翻訳・筆順を捏造しません。全 Unicode 漢字や存在し得る全英単語の網羅を意味しません。

漢字の読みは JMdict の一般的な用例と利用可能な頻度情報に基づき、送り仮名形も含めて並べます。グループ参照と初期音声は同じ順序に従い、漢字再生は常に最初の読みを使います。既存英単語カードには一つの IPA を収録し、参照項目は優先する英国発音内の原資料の順序を他の方言より先に維持します。発音頻度は文脈に依存し、原資料は全ての読みの普遍的順位を提供しません。

## 参照項目の完全な読みの録音

日本語はさらに `data/audio/reference/` の容量制限付きバンクに、完全な読みのニューラル音声 2,913 件を同梱します。初期録音と合わせて、原資料で読みが分かる全 12,356 字の優先読みに対応します。残る 752 字には読みが記録されておらず、音声を捏造しません。索引は最初の読みを選び、ファイル範囲と中断を確認します。`python3 scripts/reference-audio.py plan --work <directory>` で計画を作り、合成スクリプトで一覧を処理し、`pack` で容量制限付きバンクを生成します。

日本語の並べ替えツールは `--dictionary <JMdict.gz> --kanji-dictionary <KANJIDIC2.xml.gz> --output <priorities.json>` と任意の `--content-root data/library/content` に対応します。一般的な独立語の読みを優先し、他の読みは実在語の対応付けを頻度で重み付けして並べ、`data/audio/primary-readings.json` の確認済み単字カード用の指定を維持します。連濁と促音化は原資料の標準読みに戻して集計します。訓・音・名乗りの読みを保持し、選択された最初の読みだけが再生とキャッシュ識別を決めます。頻度情報は順序付けの手掛かりであり、全発音に通用する普遍的な頻度測定ではありません。

## 任意の音声連携

ElevenLabsを任意のモジュール依存関係として宣言します。インストール時に音声合成用として選択できますが、未導入でもStudyの有効化と録音・結合音声を使用できます。

## 特権なしで音声機能を公開

モジュール自身の名前空間で `elevenlabs-tts:synthesis` を公開し、特権フラグを削除します。英語・日本語Studyは既存の任意依存関係を利用し、ctx経由で機能を解決します。Studyの橋渡し処理は呼び出し側から現在の機能を取得する関数を受け取り、無効化・再有効化と設定済み音声に対応します。

## 音声機能を任意に維持

公開機能は `configured` で現在の準備状態を通知します。StudyはAPIキーと既定の声が保存された後にのみ自動音声を有効にします。ElevenLabsが未導入・無効・未設定でも言語登録は成功し、アップロード音声と既存音声の結合を利用できます。合成は要求しません。

## メディアを同梱しないインストールを修正

データ専用コンテンツパックから未使用のアセットディレクトリ宣言を削除し、パックのバージョンを更新します。パッケージ対象のファイルだけで一時インストールを作成し、宣言されたパスを検証することで、空のローカルディレクトリに依存する有効化を防ぎます。

## 一貫した指定音声を同梱

発音を持つすべての厳選カードと、到達可能な複数形・動詞や副詞の派生形に言語ごとの指定音声を同梱します。文のWAVには、選択した活用形を含む構成音声のPCMを順番にそのまま使用します。音声・モデル・要求の出所、チェックサム、無音検証を記録し、認証情報は含めません。

## 保存される学習設定

学校を含む小書き仮名の語の音声を、利用可能なら漢字表記を使い、指定の日本語音声・安定した設定で再生成しました。同梱の文は修正した音声から組み直します。イ形容詞とナ形容詞に副詞形・否定形・過去形を追加し、同梱語の各形に専用音声を用意します。英語の複数形にも専用音声があり、形を選ぶとその録音を再生します。

## 参考画像

任意の画像リストフィールド、非公開の画像アップロード、詳細ギャラリーを追加します。両言語モジュールにライセンス表記付きの参考写真を同梱し、すべてのレイヤーで同じフィールドを提供します。

## 文全体の直接録音

同梱文は直接生成した文全体の録音を結合音声より優先します。新しい文や録音のない文には、構成要素の PCM と選択した活用形を順序通りに使うホストの結合処理を適用し、派生形の欠落を基本形で代用しません。対象は厳選パックであり、辞書の全項目や任意のユーザー作成文ではありません。 音声 `xya0RvcJtofTcFTOdX4E` による新規の文録音を34件同梱します。日本語は仮名124クリップを再生成し、ローマ字ではなく仮名・漢字を送信します。モデル、速度、類似度、シード、音声の出典を記録します。

## 語彙の参考写真

厳選された語彙カード33件に参考写真を同梱しました（画像ファイル32件）。具体的な名詞すべてと、視覚的に明確な動作・性質を対象とし、文法・代名詞・その他の抽象概念には誤解を招く穴埋め画像を付けません。花/鼻、橋/箸、雨/飴、紙/髪/神などの日本語同音異義語には別々の画像を割り当てています。既存のカード詳細ギャラリーと画像全体のプレビューからローカル画像を読み込みます。出典の題名、作者、画像ごとの Creative Commons またはパブリックドメインのライセンス、チェックサムは[画像カタログ](../../data/library/assets/images/catalog.json)と[写真のクレジット](../../data/library/assets/images/LICENSE.md)に記録しています。ユーザー独自のカード画像は、プロバイダーの再読み込み後もホストによって保持されます。

## 語彙のイラスト

同梱されるすべての語彙カードに、それぞれ固有のアニメ調の生成イラストを追加しました（70件）。具体的な物、動作、抽象概念を説明する場面を、既存のカード詳細ギャラリーと画像ポップアップに表示します。従来の出典写真は置き換えました。[画像カタログ](../../data/library/assets/images/catalog.json)に生成元、画風、切り出し情報、チェックサム、カードとの対応を記録し、[画像ライセンス](../../data/library/assets/images/LICENSE.md)に同梱画像の扱いを記載しています。画像はローカルから読み込まれ、プロバイダーの再読み込み時もユーザー独自の画像はホストが保持します。

## 身近なものの語彙

家具、衣類、日用品、食べ物の名詞15件に、4言語の意味、発音リンク、専用録音、「身近なもの」のデッキを追加しました。英語の可算名詞には録音付きの複数形変換を用意し、fish は同形複数、rice は不可算名詞として扱います。日本語の初級者向け表記では、テーブルやコートで使う長音符「ー」を含め、完全な読みを個々のかなへリンクします。
